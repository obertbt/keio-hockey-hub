# 部のチャンネルとつなぐ（動画の自動取り込み）

部の YouTube チャンネルに上げた動画を、自動でこちらに登録します。
題・撮影日・長さ・サムネイルも一緒に入ります。

**設定は最初の一度だけ**です。以降は押すだけ、または放っておけば入ります。

---

## なぜ認証が要るのか

部の映像は**限定公開**で置いてあります。

限定公開の動画は、外から一覧を引けません。リンクを知っていれば見られますが、
「そのチャンネルにどんな動画があるか」は、持ち主にしか分かりません。
これは YouTube がそう作っているもので、こちらでは変えられません。

そのため、**チャンネルの持ち主が一度だけ許可を出す**必要があります。
許可を出すと、こちらは「動画の一覧を読む」ことだけができるようになります。

求めるのは読む権限だけです。**動画を変えたり消したりはできません。**

---

## 1. Google 側の準備（10分・一度だけ）

チャンネルを持っている Google アカウントで作業してください。

### 1-1. プロジェクトを作る

<https://console.cloud.google.com/> を開き、上部の選択から **新しいプロジェクト**。
名前は `keio-hockey-hub` などで構いません。

### 1-2. YouTube Data API を有効にする

**API とサービス → ライブラリ** で `YouTube Data API v3` を探して **有効にする**。

### 1-3. 同意画面を作る

**API とサービス → OAuth 同意画面**

| 項目                 | 入れるもの       |
| -------------------- | ---------------- |
| User Type            | 外部             |
| アプリ名             | 慶應ホッケーハブ |
| サポートメール       | 自分のアドレス   |
| デベロッパーの連絡先 | 自分のアドレス   |

**スコープ**では `https://www.googleapis.com/auth/youtube.readonly` を追加します。

**ここがいちばん詰まります。** 次のどちらかを必ず行ってください。

**A. 本番に切り替える（おすすめ）**

**対象（Audience）→ アプリを公開** を押します。
「確認が必要」と出ますが、**審査は要りません**。
求めているのが読み取りだけで、機密スコープに当たらないためです。

これで、テストユーザーの登録も、7日での失効もなくなります。

**B. テストユーザーに足す**

**対象（Audience）→ テストユーザー → + Add users** に、
チャンネルを持っているアカウントのアドレスを入れます。

> ここに入れ忘れると、許可の画面でこうなります。
>
> ```
> アクセスをブロック: ... は Google の審査プロセスを完了していません
> エラー 403: access_denied
> ```
>
> **テストのままだと、許可は7日で切れます。**
> 切れたらつなぎ直しになるので、A をおすすめします。

### 1-4. 認証情報を作る

**API とサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID**

| 項目                       | 入れるもの                                     |
| -------------------------- | ---------------------------------------------- |
| アプリケーションの種類     | ウェブ アプリケーション                        |
| 名前                       | 何でも構いません                               |
| 承認済みのリダイレクト URI | `https://〇〇.vercel.app/api/youtube/callback` |

`〇〇` は、いま使っているアドレスに置き換えてください。
**このアドレスが1文字でも違うと、最後の一歩で止まります。**

作ると **クライアント ID** と **クライアント シークレット** が出ます。控えてください。

---

## 2. アプリ側の設定（3分）

Vercel の **Settings → Environment Variables** に2つ足します。

```
GOOGLE_CLIENT_ID     = 控えたクライアント ID
GOOGLE_CLIENT_SECRET = 控えたクライアント シークレット
```

どちらにも `NEXT_PUBLIC_` を付けないでください。
付けるとブラウザに配られ、誰でも使えるようになります。

入れたら **Deployments → ⋯ → Redeploy**。環境変数は作り直さないと反映されません。

---

## 3. つなぐ（1分）

アプリで **設定 → チャンネル連携 → Google で許可する**。

チャンネルを持っているアカウントでログインします。

> **ブランドアカウントを使っている場合、ここでチャンネルの選択が出ます。**
> 個人のチャンネルと、部のチャンネル（例: `Keio girls hockey 2026`）が並びます。
> **必ず部のチャンネルのほうを選んでください。**
> 個人のほうを選ぶと、動画が1本も見つかりません。

許可すると戻ってきて、**つながったチャンネル名が表示されます**。
そこが部のチャンネルになっているか、必ず確かめてください。
違っていたら「つなぎを解く」を押して、選び直してください。

**いま取り込む**を押すと、最初の取り込みが走ります。

---

## 取り込みの決めごと

| 決めごと                                     | 理由                                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 取り込んだ動画は**部内全員**に見せる         | YouTube 側で既に部員が見られる。こちらだけ狭くしても隠したことにならず、「見たいのに見えない」を作るだけ |
| **非公開の動画は取り込まない**               | 持ち主が「まだ出さない」と決めたもの                                                                     |
| 限定公開は取り込む                           | 部の映像はこれが普通                                                                                     |
| **人が直した題を、次の取り込みで戻さない**   | 戻ると「触ると壊れる」と思われて、誰も直さなくなる                                                       |
| 空いているところ（長さ・サムネイル）だけ補う | 同上                                                                                                     |
| 何度流しても結果が変わらない                 | 押し間違いを怖がらなくてよい                                                                             |

---

## 動画ごとに、見せる相手を手で変える

取り込んだ動画は「部内全員」で入ります。
ただし、他校との練習試合など、部内でも広げたくないものはあります。
そのときは1本ずつ変えられます。

### やり方

1. **動画** を開き、その動画を押す
2. 画面をいちばん下まで送ると **「この動画を見られる人」** があります
3. **「コーチとスタッフまでに狭める」** を押す

いま誰が見られるかは、その上に出ています。
戻したいときは、同じところに **「部内全員に見せる」** が出ます。

### 誰が押せるか

| その動画を                       | 狭める | 部内全員へ広げる         |
| -------------------------------- | ------ | ------------------------ |
| 自分で上げた（取り込みも含む）   | できる | できる                   |
| ほかの人が上げた（コーチとして） | できる | **できません**           |
| ほかの人が上げた（選手として）   | 不可   | 不可（ボタンが出ません） |

**コーチでも、ほかの人が上げた動画を部内全員へ広げることはできません。**
選手が自分で撮った切り抜きを、本人の知らないところで全員に出せてしまうと、
「上げると見られる」と思われて、誰も上げなくなるためです。
広げたいときは、上げた本人に押してもらってください。

部のチャンネルから取り込んだ動画は、**つないだ人が登録者**になります。
つないだのがコーチであれば、取り込んだ動画はコーチが自由に動かせます。

### 気をつけること

ここで狭めても、**YouTube 側の公開設定は変わりません**。
限定公開のままなので、リンクを知っている人は YouTube では見られます。
本当に見せたくない動画は、YouTube 側で「非公開」にしてください。
非公開にしたものは、次の取り込みでは入りません（すでに入っているものは残ります）。

## 自動で取り込む

押さなくても入るようにします。**設定は2つだけ**です。

### 1. 合言葉を作って入れる

誰でも取り込みを叩けては困るので、合言葉で守ります。

長い乱数を作ってください。作り方が分からなければ、
<https://www.random.org/strings/?num=1&len=32&digits=on&upperalpha=on&loweralpha=on&format=plain>
を開くと1つ出ます。

Vercel の **Settings → Environment Variables** に足します。

```
CRON_SECRET = （いま作った長い文字列）
```

**Production にチェックを入れてください**（定期実行は本番で動きます）。

> 合言葉が未設定なら、定期実行の入口は**閉じたまま**です。
> 「設定を忘れたら誰でも通れる」が、いちばん危ない作り方なので、そうしてあります。

### 2. 時刻を決める

`vercel.json` をリポジトリの根に置いてあります。既定は**毎日 21:00（日本時間）**です。

```json
{
  "crons": [{ "path": "/api/youtube/sync", "schedule": "0 12 * * *" }]
}
```

`schedule` は **UTC** です。日本時間から9時間引いた値を書きます。

| やりたいこと   | 書く値         | 意味                                 |
| -------------- | -------------- | ------------------------------------ |
| 毎日 21:00     | `0 12 * * *`   | 練習が終わったころ（既定）           |
| 毎日 6:00      | `0 21 * * *`   | 前の晩の動画を朝に                   |
| 6時間ごと      | `0 */6 * * *`  | 上げてから最大6時間で入る            |
| 平日だけ 21:00 | `0 12 * * 1-5` | 月〜金                               |
| 1時間ごと      | `0 * * * *`    | いちばん早いが、無料枠では上限に注意 |

書き方は `分 時 日 月 曜日` です。変えたい場合はこのファイルを直してください。

> **Vercel の無料枠では、定期実行は1日2回までです。**
> それ以上にしたい場合は、下の「外の定期実行を使う」をご覧ください。

### 3. 反映する

`vercel.json` を変えたら push、環境変数を変えたら **Redeploy**。
どちらも作り直さないと反映されません。

**Deployments → 最新 → Functions** に `/api/youtube/sync` が出ていれば、
定期実行が登録されています。**Settings → Cron Jobs** でも一覧が見られます。

---

### 動いているか確かめる

**設定 → チャンネル連携** を開くと、こう出ます。

```
最後の取り込み    2026-08-13 21:00
そのときの結果    3本を取り込みました、12本は変更なし。
```

自動で走った分もここに出ます。**朝いちばんに見て、時刻が昨日の夜になっていれば動いています。**

失敗していれば、そのときの理由もここに残ります。

---

### 外の定期実行を使う（回数を増やしたいとき）

Vercel の無料枠が足りない場合は、外のサービスから呼べます。
<https://cron-job.org> などが無料で使えます。

| 項目     | 入れるもの                                       |
| -------- | ------------------------------------------------ |
| URL      | `https://〇〇.vercel.app/api/youtube/sync`       |
| 方式     | GET または POST（どちらでも動きます）            |
| ヘッダー | `Authorization: Bearer （CRON_SECRET と同じ値）` |
| 間隔     | 好きな間隔（15分ごとなども可）                   |

この場合、`vercel.json` の `crons` は消しておいてください。二重に走ります。

## うまくいかないとき

| 症状                                         | 原因                                                                                                                                                       |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「手続きの途中で情報が合わなくなりました」   | 時間が経ちすぎたか、別の画面から戻ってきた。最初からやり直す                                                                                               |
| 「更新トークンが返りませんでした」           | 以前の許可が残っている。Google アカウントの[サードパーティ アプリとサービス](https://myaccount.google.com/connections)からこのアプリを削除して、つなぎ直す |
| **403: access_denied**（アクセスをブロック） | そのアカウントがテストユーザーに入っていない。**対象（Audience）**で「アプリを公開」するか、テストユーザーに足す                                           |
| 「Google への接続が切れています」            | テストユーザーの7日が切れた。つなぎ直す                                                                                                                    |
| リダイレクト URI のエラー                    | 1-4 で入れたアドレスと、いま使っているアドレスが違う                                                                                                       |
| 動画が1本も入らない                          | つなぐチャンネルを間違えている（個人のほうを選んだ）か、すべて非公開。まず画面のチャンネル名を確かめる                                                     |

## 鍵の扱い

預かるのは Google の**更新トークン**です。
これは「そのチャンネルの動画一覧を、いつでも読める鍵」に等しいので、
パスワードと同じ重さで扱っています。

- ブラウザへ渡しません
- **ログインした利用者からも読めません**。管理者であっても、画面から鍵そのものを見る用はありません
- 読めるのはサーバ側だけです（`youtube_connections` に `authenticated` の権限を与えていません）
- 記録にも残しません

詳しくは [security.md](security.md) を参照してください。
