# スマートフォンに通知を届ける

コーチからの返事や、名前を呼ばれた書き込みが、**ロック画面に出る**ようにします。

LINE のように鳴ります。アプリを開いていなくても届きます。

---

## 先に知っておいてほしいこと

**iPhone・iPad は「ホーム画面に追加」しないと届きません。**

Safari で開いているだけでは、通知の許可を求める窓すら出せません。
これは Apple がそう決めているもので、こちらでは変えられません。

Android は追加しなくても届きます。

---

## 1. 鍵を作る（管理者・一度だけ）

パソコンがあれば、リポジトリで次を実行します。

```bash
pnpm vapid
```

3つの値が出ます。

```
NEXT_PUBLIC_VAPID_PUBLIC_KEY = B...（長い文字列）
VAPID_PRIVATE_KEY            = ...（長い文字列）
VAPID_SUBJECT                = mailto:あなたのメールアドレス
```

パソコンが無い場合は、<https://www.attheminute.com/vapid-key-generator> のような
生成ページでも作れます（作った鍵はそのページに残りません）。

> **`VAPID_PRIVATE_KEY` に `NEXT_PUBLIC_` を付けてはいけません。**
> 付けるとブラウザに配られ、誰でも部員に通知を送れるようになります。
>
> 逆に `NEXT_PUBLIC_VAPID_PUBLIC_KEY` のほうは**付けるのが正しい**です。
> ブラウザに渡すことが仕組みとして決まっており、それだけでは通知を送れません。

> **作り直さないでください。** 鍵を変えると、それまでに登録した端末には
> 届かなくなります。全員に登録し直してもらうことになります。

## 2. Vercel に入れる（3分）

**Settings → Environment Variables** に3つとも入れて、
**Deployments → ⋯ → Redeploy**。

環境変数は作り直さないと反映されません。

## 3. SQL を1回流す

`supabase/updates/0028.sql` を Supabase の **SQL Editor** に貼って実行します。
端末の登録を入れておく表を作ります。

---

## 4. 部員に登録してもらう

### Android の人

1. **設定** を開く
2. **スマートフォンへの通知** の **この端末で通知を受け取る** を押す
3. 「通知を送信しますか？」に **許可**

これで終わりです。

### iPhone・iPad の人

先に**ホーム画面に追加**します。

1. Safari でアプリを開く
2. 下（機種によっては上）の**共有ボタン**（四角に上矢印）を押す
3. **ホーム画面に追加** を選ぶ
4. **追加** を押す
5. **ホーム画面にできたアイコンから開き直す**

そのうえで、

6. **設定** → **この端末で通知を受け取る** を押す
7. 「通知を送信しますか？」に **許可**

> Safari のタブから開いたままだと、手順6のボタンが出ません。
> 代わりに追加の手順が出るので、そこから進めてください。

---

## 何が届くか

**あなた宛のものだけ**です。部内の書き込みが全部鳴ることはありません。

| 出来事                         | 届く人                             |
| ------------------------------ | ---------------------------------- |
| 日報にコーチがコメントした     | 日報を書いた本人                   |
| 日報の質問でコーチを呼んだ     | 呼ばれたコーチ                     |
| 動画で名前を呼ばれた           | 呼ばれた人                         |
| 動画に誰も呼ばずに書き込まれた | コーチ・スタッフ                   |
| 書き込みに返信が付いた         | 元の書き込みをした人 ＋ 呼ばれた人 |

通知を押すと、その日報や動画のその場面に飛びます。

同じ場所についての通知が続いたときは、**後のもので置き換わります**。
開くまでに同じ知らせが5件並ぶ、が起きないようにしてあります。

---

## やめたいとき

**設定** → **この端末では受け取らない**。

登録した端末が並んでいるので、使わなくなった端末はそこから **解除** できます。

端末を初期化したり、アプリを消したりした場合は、
こちらで気づいて**自動で片付けます**（送って届かなかった時点で消します）。

---

## 届かないとき

| 症状                             | 原因                                                   |
| -------------------------------- | ------------------------------------------------------ |
| ボタンが出ず、追加の手順が出る   | iPhone で、ホーム画面に追加していない                  |
| 「まだ設定されていません」と出る | 管理者が鍵を入れていない（手順1〜2）                   |
| 「許可しない」になっている       | 端末の設定 → 通知 から許可し直す                       |
| 登録したのに来ない               | いったん解除して、登録し直す                           |
| ホーム画面から開いても出ない     | 追加し直す（古い追加は仕組みが入っていないことがある） |

**アプリの中のお知らせは、通知が届かなくても残ります。**
通知はあくまで気づくためのもので、記録そのものは消えません。

---

## 仕組みの話

- ブラウザ標準の Web Push を使っています。特定の会社に依存しません
- 通数の制限も課金もありません
- 送り先（endpoint と鍵）は、**本人以外には見えません**。
  コーチにも管理者にも見せていません（`push_test.sql` で固定）
- 送るのはサーバだけです。送り先を引く関数は、画面からは呼べません
- 送り先や鍵そのものは、記録にも残しません

詳しくは [security.md](security.md) を参照してください。
